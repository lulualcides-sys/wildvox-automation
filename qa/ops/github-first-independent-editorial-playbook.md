# WildVox — GitHub-first independent editorial / TikTok release (no paid browser)

## Supported execution path

This is the normal low-cost path for the active hourly WildVox autocorreção automation. **No TinyFish, no browser credits, no user checkout or manual click.** GitHub Actions creates video candidates; the connected GitHub tool exposes each original ZIP, and local FFmpeg/image inspection establishes independent editorial evidence. The connected Metricool tool handles TikTok @wildvox only. This runbook is operational guidance, **not permission for technical CI to clear editorial review**.

1. Resolve the current **America/Sao_Paulo** local date. Read `refs/heads/main` commit SHA and `configs/daily.json` blob via the GitHub connector. Daily Prep owns 04:00 editorial replacement; never silently repurpose yesterday's footage.
2. Read Metricool brand **7242311**, assert `networksData.tiktokData === "wildvox"`, and get today's scheduled posts plus TikTok published analytics. Reject repeats by key, revision, config/media fingerprints, caption, media URL, and slot; cap at five distinct posts.
3. Fetch current GitHub Actions runs with `mcp__GitHub__fetch` on `https://api.github.com/repos/lulualcides-sys/wildvox-automation/actions/runs?per_page=50`; identify the exact run head configuration and completed per-video artifacts. Never reuse an old MP4 when `daily.json` changed.
4. Download **each candidate's actual original artifact ZIP** via `mcp__GitHub__download_workflow_artifact`. The returned ZIP is materialized as a local artifact, typically `/mnt/data/<chosen-file-name>.zip` (use the exact returned path; never guess). Extract the actual MP4, `_meta.json`, `_review.jpg`, and eight `_source_XX_preview.jpg` files; inspect these assets visually, not merely CI outcome.
5. Independently decode full MP4 in FFmpeg and sample hook, every narration segment, action and payoff. Validate species and claims, chronological source-to-script alignment, 30–45s duration, at least eight distinct sources and six authentic video clips, source count 8–12, <=8-second shots, captions in TikTok safe area, no black bars/generic filler/synthetic zoom, AAC narration, no extended repeat/freeze. Natural low-motion source clips require direct frame comparison; a threshold-only freezedetect false-positive is not categorical.
6. Confirm original creator, source page, commercial-use permission, license URL, modification disclosures and full numbered source credits in the planned caption. Prefer CC0, public domain or properly attributed CC BY. Do not mark a candidate approved if any visible claimed action is missing, even when that action happens elsewhere in the *unselected source footage*.
7. Verify `_meta.json.config_sha256` matches the selected candidate's **current** config; verify the extracted local MP4 `sha256` and `git hash-object`. Fetch the public root `media` branch tree via GitHub `git/trees/media?recursive=1`, confirm exact current MP4 Git blob SHA, metadata Git blob SHA and direct HTTPS media URL. Technical QA plus archive are necessary but **not sufficient**.
8. Commit a per-candidate `qa/reviews/<date>-<key>-<rev>-independent-editorial-approval.json` with `APPROVE` or `VETO`, current config_sha256, actual MP4 SHA256, run and artifact IDs, inspected evidence, risk notes. Do not erase unrelated approved media. `publication_hold=true` remains until independent approval exists; as precedent, approval receipt may grant a one-time slot without changing candidate bytes.
9. **Immediately before each schedule** repeat Metricool brand verification, scheduled posts and TikTok published analytics. Publish no old clips and never backdate. Use only future local slots 10:05, 12:40, 16:10, 19:35 and 22:05, exact `providers:[{"network":"tiktok"}]`, `autoPublish:true`, `draft:false`, full audited caption and exact current MP4 URL.
10. Confirm a new Metricool post ID and TikTok `PENDING` via a **fresh** `getScheduledPosts` readback; write that post ID/status/UUID to the same editorial approval JSON. **Do not claim posted/published** until provider `PUBLISHED` and an exact @wildvox public URL/ID is confirmed. Rate limits or connection errors preserve media and approvals rather than causing risky duplicate retries.
